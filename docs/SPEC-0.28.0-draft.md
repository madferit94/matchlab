# 0.28.0 초안 · StatMuse·Understat 없는 승무패 예측 모델 (설계만, 구현 전)

상태: **초안(구현 금지)**. 2026-11-02 작성. 아래 "결정 필요" 항목을 사용자가 정한 뒤에만 구현한다.

## 1. 왜 필요한가
- 지금 예측 모델(`modeling/logistic-111-2026-10-07-v01`)은 입력 111개를 쓴다. 그중 StatMuse 경기별 지표 60개와 Understat xG·npxG·deep·PPDA 지표 44개는 이 컴퓨터에서 새로 받을 수 없다(Understat 접속 불가, StatMuse 자료는 쓰지 않기로 결정). 그래서 0.27.0에서는 새 예측을 만들지 않았다.
- 목표: football-data.co.uk 공개 CSV만으로 입력을 다시 설계하고, 기존 모델과 같은 평가 기간에서 비교한다. 쓸 만하면 2026-10-26 이후 경기 예측을 새로 만든다.

## 2. 먼저 정할 것 (결정 필요)
1. **이용 조건**: football-data `data.php`에는 "개인용이며, 상업용이나 자동 봇·스크레이퍼·AI를 쓰는 데이터 학습 제품용이 아님"이라는 문구가 있다. 이 자료로 모델을 학습해 공개 사이트에 예측을 싣는 일은 이 문구와 겹친다. 운영자에게 문의해 허락을 받거나 사용자가 판단하기 전에는 학습하지 않는다.
2. **대안 경로**: 사용자 윈도우 PC에서 기존 수집 코드(Understat·StatMuse)를 돌릴 수 있으면, 기존 111 모델을 그대로 쓸 수 있다. 계수는 저장소에 있고, 입력 계산은 2026-10-21 검사에서 641경기 예측까지 같은 값으로 재현했다. 단 StatMuse를 쓰지 않기로 한 결정과 충돌한다.
3. **채택 기준**(측정 전에 고정, 통과시키려고 바꾸지 않음). 제안은 아래와 같다.
   - 2025/26 758경기 로그 손실이 기존 111 모델(1.0229)보다 0.01 넘게 나쁘지 않을 것
   - 10구간 보정 오차(ECE) 0.05 이하
   - 리그별로도 리그 빈도 기준보다 나을 것
4. **배당 사용 여부**: 0.24.0에서 배당만 쓴 모델(2025/26 정확도 52.1%)이 지표 모델보다 나았다. 이번 기본 모델은 기존 모델과 같은 조건으로 비교하기 위해 배당을 빼고, 배당은 별도 비교 기준으로만 쓰는 것을 제안한다.

## 3. 쓸 자료
- 파일: `mmz4281/{2223,2324,2425,2526,2627}/{E0,SP1}.csv`. 2022/23은 2023/24 직전 시즌 사전값(prior)에만 쓴다.
- 쓰는 열(`notes.txt`에 정의된 경기 기록)
  - 날짜·시각: Date, Time
  - 팀: HomeTeam, AwayTeam
  - 점수: FTHG/FTAG, HTHG/HTAG
  - 슈팅: HS/AS, 유효 슈팅 HST/AST
  - 코너: HC/AC, 파울: HF/AF
  - 경고·퇴장: HY/AY, HR/AR
- 쓰지 않는 열
  - HxG·AxG: `notes.txt`에 정의가 없고 공급원도 밝혀져 있지 않다. Understat xG와도 다르다(0.27.0 대조에서 평균 차이 0.26~0.29골).
  - 심판: 입력으로 쓰기에 근거가 약하다.
  - 배당: 위 2.4에 따라 기본 모델에서 뺀다. 비교 기준으로 쓰더라도 마감 배당(…C 열)은 예측 시점에 없으므로, 미래 예측 입력에 쓰지 않는다.
- 경기 연결
  - 2023/24~2025/26: `modeling/odds-0.24.0/matching.csv`(2,399경기 중 2,397경기 연결)와 같은 팀 이름 표를 써서 기존 경기 ID에 붙인다. 그래야 기존 모델과 같은 경기로 비교할 수 있다.
  - 2026/27: `tools/football_refresh` 방식으로 붙인다.

## 4. 입력 설계 (경기일 이전 자료만)
- 팀마다(팀 A = 홈, 팀 B = 원정) 지표 14개
  - 승점, 득점, 실점
  - 슈팅, 상대 슈팅, 유효 슈팅, 상대 유효 슈팅
  - 코너, 상대 코너
  - 파울, 상대 파울
  - 경고, 퇴장
  - 전반 득실차
- 각 지표를 두 가지로 계산한다.
  - **시즌값** = (이번 시즌 경기 합 + 8 × 사전값) / (경기 수 + 8)
  - **최근 5경기값** = (최근 5경기 합 + 3 × 시즌값) / (경기 수 + 3)
- 여기에 최근 5경기 승·무·패 비율 3개를 더한다. 비율은 리그 빈도를 3경기만큼 섞는다.
- 사전값 계산
  - 기본: (직전 시즌 합 + 8 × 리그 평균) / (직전 시즌 경기 수 + 8)
  - 직전 시즌 기록이 없는 승격팀: 앞선 시즌 승격팀들의 첫 10경기 평균. 이전 시즌 자료만 쓴다.
- 그 밖의 입력: 리그 표시 1개, 홈 경기 표시 후보 1개.
  - 기존 모델은 두 팀 위치를 바꾼 행을 더해 학습하고 확률을 평균했기 때문에, 홈 이점이 입력에 없었다. 홈 이점을 넣을지는 검증 시즌 결과로 정한다.
- 입력 수 합계: 2 × (14 × 2 + 3) + 1~2 = 63~64개.
- 위 계산식은 기존 111 모델과 같은 방식이다. 2026-10-21 누수 검사에서 이 방식으로 저장된 입력 119,750칸을 정확히 재현했다. 같은 방식이어야 두 모델 차이를 입력 자료 차이로 읽을 수 있다.
- 시간 규칙
  - 경기일보다 엄격히 이전 날짜의 경기만 쓴다. 같은 날 경기는 모두 계산한 뒤에 기록에 더한다.
  - 보류 4경기는 기존처럼 기록에서 뺀다.
  - 미래 예측은 한 기준일 스냅샷으로 고정한다. 예정 경기 결과는 만들지 않는다.

## 5. 학습·검증
- 시간 순서로 나눈다.
  - 2023/24 학습 → 2024/25로 L2 정규화(0.01/0.1/1) 선택
  - 2023/24 + 2024/25(1,518경기)로 최종 학습
  - 2025/26(758경기)로 평가, 2026/27 수집분(현재 179경기)은 모니터링
- 기존 모델과 같은 경기·같은 지표로 비교한다.
- 결측 대체값·표준화·리그 평균은 학습 행에서만 계산한다. 검증 단계에서는 2023/24 행만 쓴다.
- 모델: 다항 로지스틱(기존과 같은 NumPy 구현, `modeling/train_baseline.py`). 트리 모델은 비교용으로만 쓰고, 선택 규칙은 2024/25 로그 손실 하나로 미리 정한다.

## 6. 적중률 비교 방법
- 같은 경기에서 지표 4개를 보고한다: 정확도(가장 높은 확률 = 실제), 로그 손실, 브라이어 점수, ECE(10구간). 리그별로도 따로 보고한다.
- 비교 대상

| 대상 | 2025/26 정확도 | 로그 손실 |
|---|---:|---:|
| 기존 로지스틱-111 | 48.2% | 1.023 |
| 리그 빈도 기준 | 45.9% | 1.067 |
| 마감 배당 기준 | 51.8% | 0.988 |
| 0.27.0 전향 비교(60경기) | 50.0% | 0.995 |

- 차이 판단
  - 2025/26 758경기에서 두 모델의 경기별 로그 손실 차이를 짝지은 부트스트랩(2,000회)으로 95% 구간까지 낸다.
  - 구간이 0을 포함하면 "차이 확인 안 됨"이라고 쓴다.
  - 정확도 몇 %p 차이만으로 우열을 주장하지 않는다(758경기에서 1%p는 약 8경기).
- 전향 검증
  - 새 기준일 뒤 경기 예측을 결과 전에 저장한다(파일 해시와 시각 기록).
  - 결과가 들어오면 0.27.0의 "경기 전 예측과 실제" 표로 비교한다.
  - 같은 경기에 기존 111 예측이 남아 있으면 둘을 나란히 보여 준다.

## 7. 누수 방지 검사 (모두 자동, 실패 시 중단)
1. 행마다 사용한 가장 늦은 기록 날짜 < 경기 날짜(같은 날 제외).
2. 변조 검사
   - 기준일(예: 2025-08-16) 이후 경기의 결과·기록을 모두 바꿔도 기준일 이전·당일 행의 입력이 바뀌지 않아야 한다.
   - 기준일 뒤 날짜의 가짜 경기를 추가해도 입력이 같아야 한다.
3. 독립 재계산: 다른 구현(검증 담당)이 입력 칸 전체를 경기 기록에서 다시 계산해 정확히 같아야 한다.
4. 평가 시즌 차단: 결측 대체값·평균·표준편차·L2 선택에 평가 시즌이 들어가지 않았는지 저장값과 재계산값을 비교한다.
5. 승격팀 사전값은 이전 시즌 자료만 쓴다. 같은 시즌 승격팀 기록을 넣으면 값이 바뀌는지 확인한다.
6. 미래 예측
   - 입력 기록은 모두 기준일 이하의 완료 경기여야 한다. 예정 경기 결과는 0개여야 한다.
   - 저장 확률은 저장 계수로 다시 계산해 같아야 한다.
7. 배당을 쓰는 비교 모델은 경기 전 배당 열만 쓴다. 마감 배당은 평가 참고로만 쓰고 미래 예측 입력에는 쓰지 않는다.
8. 2025/26 평가는 채택 기준을 정한 뒤 한 번만 계산해 기록한다. 이후 입력을 바꾸면 새 버전으로 기록하고, 이미 본 평가 기간이라고 표시한다.

## 8. 화면 반영 (구현 시)
- 기존 641개 예측은 그대로 두고 0.27.0 비교 표에 남긴다.
- 새 모델 예측은 새 기준일 뒤 예정 경기에만 붙이고, 모델 ID·입력 기준일·출처(football-data)를 표시한다.
- 새 모델의 점수 분포는 같은 입력으로 포아송 득점 모델을 다시 학습해야 한다. 그 전에는 시뮬레이션이 "예측 준비 중"을 보여 준다.

## 9. 작업량과 위험
- 작업량(구현 시)
  - 수집·연결 0.5일
  - 입력·학습·평가 1일
  - 독립 재계산·누수 검사 0.5~1일
  - 화면·문서·릴리스 0.5~1일
- 위험
  - 이용 조건
  - 입력 정보량이 줄어 성능이 떨어질 수 있음(xG·압박 지표 없음)
  - 팀 이름 연결 오류
  - football-data 값이 과거에 정정되었는지 확인할 수 없음
  - 날짜가 영국 기준이고 실제 킥오프 시각은 확인하지 않음
