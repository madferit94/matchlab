# 0.26.4 · F1 최근 완료 GP 추가 (싱가포르·미국·멕시코시티)

## 요청
- 사용자: "오늘 그랑프리 하나 끝났으니 F1에 추가하라." 오늘은 2026-11-02(KST)다.
- 범위: `f1/index.html` 자료(GP 25개, 완료 16개)에 없는 이미 끝난 2026 GP를 모두 완료 GP로 넣는다. 빠진 GP는 3개다.
  - 싱가포르 GP(세션 11388): 2026-10-11 12:00 UTC 출발
  - 미국 GP(11396): 2026-10-25 20:00 UTC 출발
  - 멕시코시티 GP(11404): 2026-11-01 20:00 UTC 출발. 한국 시각으로 11-02 05:00에 출발한 "오늘 끝난 GP"다.
  - 남은 4개(상파울루 11-08, 라스베이거스, 카타르, 아부다비)는 아직 열리지 않아 예정 그대로 둔다.
- 담당(MatchDesk): 팀장 계획·결재 → 수집 + 시각화·웹(같은 하위 에이전트) → 독립 검증. 예측 모델은 다시 만들지 않는다(누수 방지).

## 바꾸는 것
1. **수집 스크립트** `design/release-0.26.4/collect.py`
   - OpenF1 공개 API만 쓴다. 키와 로그인이 필요 없다.
   - 요청 간격은 2.1초이고, 429 응답에는 두 번까지 다시 시도한다.
   - 원자료는 저장소 밖 스크래치 폴더에 gzip으로 저장하고, 해시를 남긴다.
   - 기존 GP 2개(11731·11377)를 다시 만들어 현재 자료와 비교하는 확인 기능(`--verify`)이 있다.
2. **병합 스크립트** `design/release-0.26.4/merge.py`
   - `dataset`·`maps`·`profile-data` 세 블록만 바꾼다.
   - 블록은 처음 쓸 때와 같은 방식(`json.dumps`, `ensure_ascii=False`)으로 다시 쓰고, 이 방식이 현재 바이트를 그대로 재현하는지 먼저 확인한다.
   - 새 GP 3개의 예정 항목만 같은 위치에서 완료 항목으로 바꾼다. 나머지 GP 22개와 서킷 22개는 바이트까지 그대로 둔다.
3. **누적 자료**: `profile-data`의 현재 챔피언십 순위(드라이버·팀)와 기준 세션을 멕시코시티 GP 기준으로 바꾼다.
   - 드라이버 목록은 프로필 수집기 규칙(가장 최근 완료 GP의 드라이버 행)을 따른다.
   - 새로 나온 드라이버(50번 Ryo HIRAKAWA, 멕시코시티)를 넣는다. OpenF1에 팀이 비어 있어 팀은 빈 값이고 사진은 없다.
   - 사진 주소는 다시 모으지 않았다(`portraits_collected_at`).
4. **예측 대비 실제**: 새 GP 3개는 원래 있던 "경기 전 예측"(`forecasts`, 기준 2026-10-07, 경기 결과 반영 전)을 그대로 쓴다.
   - 예측 블록은 바꾸지 않는다. 경기 뒤 정보로 예측을 다시 만들지 않는다.
   - 화면 코드에서 완료 GP에 과거 재현 예측이 없고, 경기 전 예측이 있으며, 그 기준 시각이 출발 전일 때만 그 예측을 쓴다.
   - 비교 탭 설명은 "경기 전에 공개한 예측입니다(자료 기준 2026-10-07, 경기 결과는 쓰지 않음)."(영어 동일)이다.
5. **검사**: `tools/check_release.py`의 F1 자료 비교를 블록 통째 비교에서 GP별 비교로 바꾼다.
   - 예측 블록 3개(`forecasts`·`historical`·`tracks`)는 0.8.6과 바이트가 같아야 한다.
   - `dataset`·`maps`는 새 GP 3개 말고 모든 항목이 0.8.6과 바이트가 같아야 한다.
   - 새 GP 3개는 이전에 예정·참고 윤곽이었고, 지금은 결과·랩·위치 기록이 있어야 한다. 경기 전 예측의 기준 시각은 출발 전이어야 한다.
   - 요약 정보는 상태 수가 실제와 같아야 하고, 기존 누락 기록이 그대로 앞에 남아 있어야 한다.
6. 0.26.3 재생 동기화(`leaderSync`, `redFlagHold`)는 코드를 바꾸지 않고 새 GP에 그대로 적용한다. 멕시코시티 GP에는 적기가 한 번 있다.
