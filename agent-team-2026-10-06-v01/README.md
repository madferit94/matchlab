# MatchDesk 에이전트 팀 — 도구 독립 구조

**10개 역할, 공통 스킬 10개, Codex·Claude Code용 연결 파일과 실제 실행 가능한 자료 검사·승인 검사 코드를 만들었습니다.** AI 제공자나 모델 이름은 고정하지 않았습니다. 자료 수집 전체 자동화와 예측 모델·웹 구현은 별도 단계입니다. 참가자 확인 전입니다.

| 담당 | 책임 |
|---|---|
| 팀장 | 작업 배정·의존관계·실패 재배정 |
| 데이터·선수단 | 기본 자료와 포메이션·선발·선수단·시장가치 보조 자료 |
| 최근 팀 동향 | 부상·징계·이적·감독 변화·공식 발표 |
| 예측 | 계산 코드에 근거한 승·무·패 확률 |
| 경기 분석 | 경기력·전술·선수단 비교와 설명 |
| 시각화·웹 | 경기 비교 화면·차트·누락 상태 표시 |
| 모델 평가 | 작성자와 독립된 과거 경기 평가 |
| 검증 | 자료·계산·설명·화면의 실제 검사 |
| 운영·갱신 | 수집 실행·최신성·실패 확인 |
| 최종 승인 | 근거 검토 후 승인·반려·보류 |

사용자님은 출처 정책 변경·모델 채택·공개 배포의 최종 결재권자입니다. AI 승인은 내부 분석 결과의 승인입니다.

## 추가한 수집 항목

`context-data-contract.json`에 포메이션, 선발 명단, 선수단 구성, 선수단 시장가치, 부상·징계·출전 가능 상태, 감독, 이적, 소식, 휴식일 형식을 정의했습니다. 데이터·선수단 담당과 최근 동향 담당 스킬이 이 자료를 수집하고 검사하도록 연결했습니다.

- 기본 경기·일정·xG는 기존 Understat 선택을 유지합니다. StatMuse 추가47종과 보조 정보는 별도 자료입니다.
- 실제 선발과 예상 선발을 구분합니다. 실제 선발은 서로 다른 선발 선수11명을 확인해야 합니다.
- 포메이션은 명목 시작 배치와 예상 배치를 구분합니다. 경기 중 실제 위치까지 확인했다고 주장하지 않습니다.
- 시장가치는 평가 기준일·통화·금액·선수/선수단 범위를 저장합니다. 추정값이며 구단 기업가치·실제 이적료로 쓰지 않습니다.
- 모든 항목에 팀 키·출처 URL·확인 시각·정보 상태를 붙입니다. 부상 정보는 미래 경기 결장을 자동으로 확정하지 않습니다.
- 보조 정보가 없으면 MISSING/BLOCKED와 이유를 남깁니다. 값0으로 채우지 않습니다.
- 보조 정보는 우선 설명용입니다. 당시 알 수 있었던 자료와 평가가 준비되기 전에는 과거 예측 특징에 넣지 않습니다.

포메이션·선발 후보 출처는 FotMob, 시장가치 후보는 Transfermarkt, 동향은 구단·리그 공식 발표입니다. [FotMob 경기 정보](https://www.fotmob.com/matches/liverpool-vs-west-ham-united/2h59kq)를 읽어 기능을 확인했습니다. Transfermarkt 정의 페이지는 이번 조회에서 실패했습니다. 실제 모든 팀·경기 수집 연결은 검증되지 않았습니다. 후보와 상태는 source-routing.json에 있습니다. **새 보조 정보 실제 수집 건수는 현재0이며, 작성한 테스트 선수·금액은 합성 검사 입력으로만 사용했습니다.**

## 두 도구에서 쓰는 방법

이 폴더를 프로젝트 작업 폴더로 사용합니다. 공통 원본은 `skills/`, 역할 문서는 `roles/`, 작업 연결은 `team.json`입니다.

- Codex 연결: `AGENTS.md`와 `.agents/skills/`의 공통 스킬 사본. 실제 환경이 제공하는 하위 에이전트 도구에 해당 역할을 배정합니다. [OpenAI 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)
- Claude Code 연결: `CLAUDE.md`, `.claude/agents/`의10개 하위 에이전트 정의, `.claude/skills/`의 스킬 사본. [Claude 스킬 문서](https://code.claude.com/docs/en/skills), [하위 에이전트 문서](https://code.claude.com/docs/en/sub-agents)
- model/provider는 고정하지 않았습니다. 도구의 기본 선택을 따르고, 결과 보고서에는 실제 사용한 도구·모델을 알 수 있을 때 기록합니다.
- 병렬 기능이 없으면 같은 입출력 형식으로 순차 실행할 수 있습니다. 순차 자가검사를 독립 검증으로 표시하지 않습니다.

**이 세션에서 Claude Code 실제 실행이나 두 도구의 자동 발견은 테스트하지 않았습니다.** 패키지 폴더를 열어 로드해야 하며 지금 열려 있는 상위 수업 폴더에 자동으로 설치됐다고 주장하지 않습니다. API 기반의 무인 실행기도 아직 없습니다.

## 실행 가능한 공통 검사

`tools/context_cli.py validate <자료.json>`은 보조 정보의 키·출처·시간대·정보 상태와 실제/예상 선발·시장가치 형식을 검사합니다. 구조 검사이며 자료의 사실 정확성 인증은 아닙니다.

`tools/approval_gate.py <보고서묶음.json>`은 analysis/prediction/web 모드별 필수 보고서, 실제 증거 파일 존재, 검사 주체의 분리, 필수 오류와 확률 합계·범위를 검사합니다. 모델·필수 근거가 없으면 HOLD, 오류는 REJECT, 필수 조건을 충족하면 APPROVE입니다. 최종 승인 에이전트는 이 코드 결과와 증거 내용을 함께 검토해야 합니다. 코드가 파일 내용의 진실성을 판단하거나 사람의 배포 승인을 인증하는 것은 아닙니다.

실행 순서와 계약은 TEAM-PROTOCOL.md와 report-contract.json을 참고합니다. 보고서 묶음은 run_id, match_key, mode, reviewer_id, reports를 포함하며 reports의 키는 역할 ID입니다. 예측 보고서는 probabilities.home/draw/away, 평가 보고서는 model_accepted를 추가합니다. 파일·결과 없이 완료 보고서를 만들지 않습니다.

## 확인 결과

- tests/test_team.py: 동작 테스트7개 통과. 잘못된 경기 참조·누락의0처리·예상 선발 확정·통화 오류·비정상값·모델 없는 확률 승인·확률 합계 오류·자가검증·범위 밖 증거를 검사했습니다.
- 10개 역할 의존관계에 순환 없음, 세 위치의 스킬 파일 내용 동일 확인.
- 스킬 기본 검사 quick_validate.py는 PyYAML 누락으로 실행 실패. 간소 형식 검사로10개 스킬의 필수 머리말·이름·설명·경로를 확인했습니다. 기본 도구 검사 통과로 표시하지 않습니다.
- 기본 데이터 원본을 변경하지 않았습니다. 예측 모델·웹·자동 갱신·새 보조 데이터 수집 완료를 주장하지 않습니다.

화면에서 위 팀 목록과 추가 수집 항목을 먼저 확인하세요. 이 패키지에 ‘아스널 다음 경기의 데이터와 동향을 확인하고 확률 없이 분석해줘’라고 요청하면 팀장이 analysis 모드로 필요한 역할을 배정하는 방식입니다. 실행에 필요한 출처 접근이 없으면 그 항목은 보류/누락으로 남깁니다.
