# 팀 공통 계약

기본 데이터 역할은 ../source-unified-2026-10-06-v01/source_policy.json을 따른다. 새 보조 정보는 context-data-contract.json으로 구분한다. 추가 자료가 없다고 기존 기본 분석을 막지는 않지만 실제로 확보하지 않은 자료를 설명에 쓰지 않는다.

팀장→데이터·최근 동향·운영→예측·경기 분석→모델 평가·시각화→검증→최종 승인 순서로 수행한다. 의존관계는 team.json이 정한다. 조회나 자료만 필요한 요청에서는 불필요한 모델·화면 작업을 생략할 수 있고 생략 사실을 기록한다.

담당자는 공통 report-contract.json으로 결과를 제출한다. run_id·match_key를 통일한다. producer_id는 실제 검사 주체를 구분한다. 같은 모델을 쓰더라도 작성자와 검사자는 다른 작업 주체로 분리한다. 별도 주체 없이 순차 자가검사한 경우 독립 검사로 주장하지 않는다. 환경이 독립 실행을 지원하지 않으면 그 한계를 명시한다.

역할 산출물과 보고서 증거는 고유한 실행 폴더에서 관리하고 재시도 결과도 보존한다. 작업 기록은 상위 실습 폴더의 작업일지.md에만 추가한다. 별도 작업일지·todo 로그를 만들지 않는다.

최종 승인자는 도구 tools/approval_gate.py의 필수 근거 검사와 실제 보고서를 검토한다. APPROVE는 내부 분석 결과의 표시 승인이다. REJECT는 수정할 오류, HOLD는 필수 자료·구현 부족이다. AI 내부 승인은 사람의 출처 변경·모델 채택·공개 배포 결재가 아니다.

Codex: 이 폴더를 작업 폴더로 열면 AGENTS.md와 .agents/skills에 역할·스킬이 있다. 현재 실행 환경에서 지원하는 하위 에이전트 기능에 roles/<role>.md를 작업 지시로 전달한다. 기능이 없으면 스킬을 읽어 순차 작업하고 독립 검사의 한계를 표시한다.

Claude Code: 이 폴더를 프로젝트로 열면 CLAUDE.md, .claude/agents, .claude/skills 정의를 사용한다. model을 지정하지 않아 실행 환경의 선택을 따른다. 두 도구의 동시 병렬 실행을 강제하거나 라이브 API 연결 완료로 주장하지 않는다.

공통 원본은 skills/이며 두 도구용 스킬 사본은 동일하다. 수정 시 세 위치를 함께 반영하고 test_team.py의 동일성 검사를 실행한다. 향후 다른 모델도 같은 역할 문서와 JSON 입출력으로 작업하도록 연결할 수 있다. 아직 API 기반 자동 실행기는 구현하지 않았다.
