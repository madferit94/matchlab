# Recorded circuit paths and selected-driver locations · 0.4.0

This package separates observed race locations from the model's symbolic predicted final-order lane. `maps.json` is keyed by the target race session key. Completed GP entries have `OBSERVED_LOCATION`, a raw-coordinate single-lap outline (`points`) and two selected drivers' time-sorted `samples` (`epoch milliseconds, x, y`). Prioritise Russell 63 and Verstappen 3 only when their actual session drivers/laps exist, otherwise use available drivers. Remaining drivers require separately labelled lap-based reconstruction; neither all-car observed locations nor genuine predicted lap-by-lap driving is claimed.

Outline and observed driver samples use the same OpenF1 raw x/y coordinate system. The outline comes from a normal recorded lap, usually lap 10, with at least 100 source samples. It is not hand drawn, geographically scaled, image-derived or artificially closed in this data. A canvas may visually connect an outline, but no extra measured point is invented. Source units/orientation are not asserted to be geographical GPS coordinates or metres.

The collector queries strict `date>` and `date<`, then filters race boundaries with a ±2.4-second allowance. The earlier `date>=`/`date<=` request returned HTTP 404; that error did not prove absent location data. Full retained JSON responses are gzip cached and hashed in `source-manifest.json`. Browser samples keep roughly one observed point per second, both ends of original intervals exceeding two seconds, and first/last points. No interpolation occurs in the stored data. Gaps remain disclosed (`max_original_gap_ms`, `original_gaps_over_2s`) and the UI must not bridge a large missing interval as observed motion.

Upcoming entries have `HISTORICAL_REFERENCE`, `reference_year: 2025`, `reference_session_key` and empty observed `drivers`. They use an earlier 2025 race with the same actual `circuit_key`; this is labelled a previous-year reference, not proof of the 2026 layout or future race movement. Neither future actual results nor target locations enter the prediction model. Cancelled GP receive no race traces.

`collect-maps.py` handles completed GP; `collect-future-references.py` adds future-circuit references. Requests are spaced 2.1 seconds apart and HTTP 429 gets one bounded retry. Every completed GP writes progress. `check-source.py` verifies hashes, raw-to-sparse coordinates, chronology, identities and circuit keys. `producer-check.json` carries current coverage and author self-check evidence; independent review is separate. Source: [OpenF1 documentation](https://openf1.org/docs/).
