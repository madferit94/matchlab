# 실제 기록으로 만든 서킷 경로와 일부 드라이버 위치 · 0.4.0

예측 레이스의 순위 연출과 실제 레이스 위치 기록을 구별합니다. `maps.json`은 대상 GP 세션 번호로 구분합니다. 종료 GP의 `OBSERVED_LOCATION`에는 실제 한 랩의 서킷 윤곽과 선택한 드라이버 2명의 `[시각, x, y]` 기록이 들어 있습니다. 해당 GP에 실제 참가한 기록이 있으면 러셀 63·베르스타펜 3을 우선하고 없으면 다른 참가자를 사용합니다. 나머지 차량은 랩 기록 기반 재구성으로 별도 표시해야 하며 전 차량의 실제 위치를 확보했다고 표현하지 않습니다.

서킷 윤곽과 차량 위치는 같은 OpenF1 원본 x·y 좌표입니다. 윤곽은 정상 랩(보통 10랩)의 원본 100개 이상 좌표에서 뽑았습니다. 임의 도식·사진 윤곽·지리 지도에서 만든 경로가 아닙니다. 데이터 끝을 강제로 시작점에 연결하거나 가짜 측정점을 추가하지 않았습니다. 이 좌표가 위성 GPS의 위도·경도나 미터 단위라고 단정하지 않습니다.

이전 수집기의 `date>=`·`date<=` 요청은 HTTP 404가 났습니다. 이것은 위치 기록이 없다는 근거가 아니었습니다. `date>`·`date<`로 조회하면 자료가 반환됐습니다. 레이스 경계 전후 2.4초 범위로 원본을 걸러 보관합니다. 전체 응답은 압축 원문과 해시로 남겼고, 화면용 자료는 약 1초에 한 원본 위치를 유지합니다. 첫점·끝점·원본 2초 이상 결측 구간의 양끝을 보존했습니다. 데이터 자체에 가짜 중간 위치를 만들지 않았습니다. 화면에서도 큰 결측 구간을 실제 주행으로 이어 그리면 안 됩니다.

예정 GP는 `HISTORICAL_REFERENCE`와 2025년 참고 경로로 표시하며 `drivers`는 비어 있습니다. 실제 같은 서킷 번호의 이전 2025년 경로이며, 올해 레이아웃이 동일하다는 공식 확인이나 미래 주행 기록이 아닙니다. 실제 대상 경기의 좌표·결과를 예측 모델 입력에 넣지 않습니다. 취소 GP는 주행 기록 대상에서 제외합니다.

`collect-maps.py`로 종료 경기, `collect-future-references.py`로 예정 경기 참고 경로를 수집합니다. 2.1초 간격으로 요청하고 호출 제한 오류는 한 번만 추가 재시도합니다. GP 하나가 완료될 때마다 진행 파일을 저장합니다. `check-source.py`가 출처 해시·원본 좌표 일치·시간순·선수·실제 서킷 연결을 검사합니다. `producer-check.json`에 실제 확보 목록과 자체 검사 결과가 있으며 독립 검증과 구분합니다. 출처: [OpenF1 문서](https://openf1.org/docs/).
