# Driver metrics and help / 드라이버 지표와 설명

F1 0.6.0 / new v09 implementation; source data and model files remain unchanged.

`MatchLabF1Metrics.calculate(race, driverNumber, prediction)` returns rows `{key,value,unit,category}`. Completed races expose 18 record metrics plus the ten stored model features, win probability and continuous expected rank (30 cards when all inputs are present). Missing values stay null/dash. A failed coverage status excludes even a leftover raw array; successful empty collections can represent a genuine count of zero.

Recorded metrics: final classification, points, completed laps, status, starting grid, grid-minus-finish change (not overtakes), positive lap-time count, best duration, mean duration, population standard deviation, mean sector 1/2/3 durations, maximum positive speed-trap reading, pit entries within the session, mean pit-lane duration, mean stationary stop duration, and stint record count. Pace includes pit-out, Safety Car, interrupted and outlier laps; lap_duration must be finite and positive. Standard deviation requires two records. Each sector uses its own positive observations, including partial laps without a total duration. Pit lane uses lane_duration or null-only legacy pit_duration fallback; stationary stop uses stop_duration only. These are different quantities. Tyre stint count is not claimed to equal pit or tyre-change count.

Model input help follows the original v04 train.py exactly: fixed strength-two shrinkage `(sum+2×prior)/(count+2)`, using priors 0.5 (rank score), 4 (points), 0.05 (win), 0.15 (podium/nonfinish). Rank score is `(field size−position)/(field size−1)`, missing position treated as last. Own recent inputs use up to five previous GP; team features use entrant result rows across the team's last five GP, not a per-GP win proportion. Same-circuit features use the driver's earlier same-circuit_key records. Stored feature values and model probabilities are displayed without retraining or recomputation.

The shared Korean/English `registry` explains all cards plus live rank/lap/status/tyre/pit/last-lap fields and progress charts. `buttonHtml(key,locale,label)` supplies a keyboard-operable label button. Click opens an anchored non-modal role=dialog; close/Escape restores focus, outside click closes while preserving the clicked control focus. Resize/scroll repositions within viewport bounds. Navigation closes stale help via stopReplay. `placeBubble` is pure for bound tests. Long explanations stay in this disclosure, not always-visible collection-source columns.

The completed GP tab offers driver and All / Race result / Lap pace / Tyres & pits / Pre-race model inputs filters. Upcoming forecasts have feature cards and probability/rank explanations without inventing actual data. Live map cards and chart labels reuse the same registry. Numeric values remain on one line; status/compound words have separate wrap styles. Tyre labels have independent full-width chips and small duration bars rather than being forced inside a narrow proportional bar.

Verification: `node replay/test-metrics.cjs` reports 15877 checks PASS across all 16 completed GP. Tests cover aggregation, null/failed collection, positive selection, population std, sector partial records, pit-vs-stop distinction, original feature preservation, all ten shrinkage explanations, bilingual text, and 320/375/768/1280 bubble geometry. Script syntax checks and assemble.py pass. Root's headless Edge tests and independent reviewer evidence are separate actual UI verification.

UI guidance applied: UI/UX Pro Max touch targets at least 44px, explicit clickable disclosures, no hidden text clipping, shrinkable responsive controls, 16px labels and at least 8px gaps. [OpenF1 definitions](https://openf1.org/docs/) distinguish lap_duration, is_pit_out_lap, lane_duration and stop_duration.
