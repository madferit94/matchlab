# 5개 에이전트 실행 규칙

팀장 계획 → 수집 → 분석·예측 → 시각화(요청에 따라 생략) → 독립 검증·모델 평가 → 같은 팀장의 최종 내부 결재.

team.json의 phases는 작업 단계이고 roles는 실제 담당 5명이다. 팀장의 계획과 결재를 별개의 AI 두 개로 세지 않는다. 검증자도 자료 검증과 모델 평가에 한 주체를 사용한다. 분석·수집·화면 작성자와 검증자/결재자의 producer_id는 달라야 한다. 최종 결재자는 검증자와도 다르다. 기능을 직접 작성한 팀장은 자신의 결과를 최종 결재하지 않는다.

보고서에는 agent_id·producer_id·run_id·match_key와 기능별 reports를 넣는다. 내부 기능 보고서 형식은 기존 report-contract.json을 유지하여 이전 검사 코드와 연결한다. 기능 보고서 10종은 10명의 에이전트를 뜻하지 않는다. 통합 담당자 이름과 실제 실행 주체를 확인한다.

tools/integrated_gate.py로 담당 배정/보고 주체를 검사하고 기존 승인 규칙을 적용한다. mode analysis는 데이터·분석·검증·운영을 요구하며, prediction은 예측·모델평가, web은 시각화도 요구한다. 선택 기능 생략은 기록한다. 최종 담당은 규칙 통과 후에도 실제 근거 내용을 읽는다. 운영 보고서의 갱신 실행 여부는 자동 갱신 구현 여부와 구분한다.

미래 경기의 실제 선발은 경기 전 미발표일 수 있다. 이를 기본 예측의 필수 조건으로 강제하지 않는다. 과거 학습에는 당시 알 수 있는 최근 기록을 넣고 실제 결과는 정답으로 사용한다. 현재 누적 통계·현재 선수단·경기 후 실제 선발을 과거 입력으로 넣지 않는다.

실제 팀 실행은 현재 환경의 하위 에이전트 기능으로 roles/<agent>.md를 전달한다. 다섯 담당을 동시에 실행할 필요는 없다. 별도 API 자동 실행기는 미구현이다. 독립 실행이 불가능한 환경에서는 자가 점검을 독립 검증이라고 부르지 않는다. Claude용 구성 파일과 Codex용 구성 파일이 있어도 양쪽 실동작을 확인했다고 주장하지 않는다.
